## 2. Type3 comment parser and conditional allocation guards (05H)
- `0x005D4030` parses a type3 comment header. Its native `0x005D4061` calls `_calloc` (`0x005D1C71`) and stores the result to `ESI+0xC`; for vendor length >0 it writes through that pointer at `0x005D407D` without a preceding local null check. A length-zero branch bypasses this write. **Potential null-write path is static, not a measured game fault.**
- With comment count >0, two further allocation calls `0x005D40BE`/`0x005D40C8` precede array stores `0x005D4112`/`0x005D411C` without local null checks; per-comment calloc at `0x005D4115` feeds the later `0x005D3CB0` helper. The zero-vendor/zero-count route and subsequent type5 vendor-pointer check (`0x005D455B`) are conditional and untested dynamically.
- CRT `_calloc` (`0x005D1C71`) calls `0x005C303C`, which invokes heap allocation and checks for null at `0x005C3085`. These CRT helpers were already identified in V9; do **not** count them as two new game-semantic discoveries or auto-rename them.
- Source/owner: REA ID `REA-LOCAL-20261031-05H-P0-VORBIS-CALLOC-NULL-GATE-STATIC-01`, `rea_lab/decomp_task/REA_20261031_05H_P0_VORBIS_CALLOC_NULL_GUARD_STATIC.md` and its evidence JSON (owner static QA 56/56; no gameplay). ## 8. Bitreader EOF and type3 vendor-length distinction (REA 07H)
- REA/T015 ID REA-LOCAL-20261031-07H-P0-VORBIS-BITREADER-EOF-BOUND-STATIC-01; source rea_lab/decomp_task/REA_20261031_07H_P0_VORBIS_BITREADER_EOF_BOUNDS_STATIC.md and corresponding EVIDENCE.json. Original PE SHA and V9 SHA appear at the top of this REF; bounded independent PE readback: 36/36 opcode sites and 12/12 E8 sites.
- 0x005E6E10 rejects bit requests above 32. Its short-packet path checks rounded required bytes; on EOF, 0x005E6EE9..0x005E6F03 sets currentPtr+0xC=NULL, cursor+0=totalSize+0x10, bitOffset+4=1 and EAX=-1. 0x005E6F10 returns cursor+ceil(bitOffset/8), which after the EOF marker can exceed total by one. Reader failure is not an observed game failure.
- Type3 routing consumes one type byte and six signature bytes, then four vendor-length bytes: normal vendor text starts at offset 11. Yet the check at 0x005D4050..55 uses L<=packetSize-8, three bytes looser than actual packetSize-11. Vendor copying stores AL without a local -1 test, but the following type3 parse can enter error cleanup after EOF. Neither successful invalid input acceptance nor an exploitable overflow is proven.
- Per-comment body length instead checks L<=packetSize-currentRoundedCursor, limiting the 06H byte-copy helper's negative-return possibility under a consistent reader. Native calls and fields are STATIC; normal-state arithmetic INFERRED; malformed-input behavior and gameplay VERIFY.
