## 3. Task/VM continuation is not a safe pause by itself
- 0x004C2935 is an instruction site INSIDE Task dispatcher function 0x004C28D0, not a standalone V9 function entry. It lies after the currently invoked Task callback and before advancement to the next index. An eligible normal GameEvent path may reach it, but null/filtered Task paths reach it too; the exact original thread/pass/owner/request token is required even for a candidate observer.
- Jumping to epilogue or returning there can skip remaining Task callbacks, pending merge, compaction and counter update; it can also break live stack/flags/SEH assumptions. An active flag or VM wait flag alone does not freeze the complete game.
- The 0x004C2714 Task loop and 0x43361B VM return have other callers/reentrant paths. The 0x004C2935 candidate has no demonstrated unbounded safe hold, preserved complete state, or production DLL ABI.
