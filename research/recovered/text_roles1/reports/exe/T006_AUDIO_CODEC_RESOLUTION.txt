[CONFIRMED-TARGET] playback core 0x4BDE40
- input filename is copied to local string.
- 0x426490 searches for literal '.' (0x630000).
- when no dot is present, core iterates pointer table 0x68C7D0..0x68C7D8 in this exact order:
  0x68C7D0 -> 0x630004 = .mid
  0x68C7D4 -> 0x63000C = .mp3
  0x68C7D8 -> 0x630014 = .ogg
- each candidate is formed by appending the suffix, then resolver 0x4BDAF0 is called.
- resolver result string length/non-empty state is tested; first successful candidate stops the loop.
- therefore extensionless basename precedence is: .mid first, then .mp3, then .ogg.
- if all three fail, playback continues with unresolved/original local state through the common later path; exact user-visible failure/no-op is still VERIFY.

[CONFIRMED-TARGET] explicit extension handling
- after resolution, core again searches for '.' using literal 0x63001C='.'.
- it extracts 3 chars after the dot and compares them against 0x630020='mp3'.
- this establishes an explicit MP3-special branch in the common playback core.
- exact downstream backend object chosen by that flag is not yet fully labeled; do not infer more than an MP3-specialized path.
