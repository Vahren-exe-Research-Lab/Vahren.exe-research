# JSONの検証モデル・分野別証拠票の回収

未収録211原本を対象とし、193出典行を検索へ追加した。同一内容の別名5件をまとめ、188本文へつなぐ。内訳は[検証モデル1](../json_models1/README.md)、[検証モデル2](../json_models2/README.md)、[分野別証拠票](../json_sources1/README.md)。件数は保存・出典の数であり、新しい発見・実機検証の数ではない。

185本文は元バイトと完全一致、2本文は個人情報の接頭辞だけを伏せた完全版、1本文はUTF16LE BOMからUTF8への損失のない完全版。元と保存先のSHA、編集区間と不変区間、再符号化による原本一致を親でも確認した。3件の保存原本は末尾が壊れたJSONのまま保持し、不完全ケース集合・構文エラーという制約を残す。勝手な補完・整形はしていない。

大きな反復配列は、全ノード・全ての異なる記述とキー・数値域・構造・宣言された組合せを確認した。全物理行を一行ずつ手読みにしたとの主張ではない。静的な証拠票、合成ケース、著者作成のモデル、識別子・件数の一覧は元の確度で保存する。ケースが保存できたことやJSONとして読めることを、実行成功・ABI確定・Golden・READYに読み替えない。

18件は具体的な既存保留対象の内部処理、戦闘後Castle処理、rsc3/rsc4資料、元のプロパティ値の大規模輸出と重なるため、全文・抜粋・再構成を保存せず[識別と理由](DEFERRED_AT_INTAKE.tsv)だけを残した。汎用語・アドレスやハッシュがあるだけでは一律に保留にしていない。[既収録1本文も保留へ訂正](LEGACY_SCOPE_CORRECTION.md)し、現在の本文・受理台帳・自動索引から外した。過去の受理だけを再利用の許可とは扱わない。

本文は研究ID・元ファイル名・所有者+オフセットから共通検索でき、個別出典のSHAと制約へ辿れる。今回、関数・正式フィールド・読み書き関係の確定数は増やしていない。リンク先の原作・native・スクリプト・DB・ログ・ケースは取得・実行していない。元のローカル文書は変更・削除していない。
