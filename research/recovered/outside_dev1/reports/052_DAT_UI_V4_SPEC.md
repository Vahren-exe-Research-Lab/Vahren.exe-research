# DAT 連携型・汎用ユニット一覧選択（profile v4）仕様

Claude 2026-10-28 / PEER_SCRIPT01_FINDINGS §91。v3（任意文字列の一覧、49件まで、実機確認済み）の上に作った、ユニット専用の一覧選択です。
教育用の処理は DLL に入れていません。DAT から渡された候補を表示し、選ばれた行を返すだけです。

## 1. DAT から呼ぶもの

| 名前 | 役割 |
|---|---|
| `routine(hk_ui_pick_unit)` | **呼び出し口**。DAT はこれだけを呼ぶ。 |
| `hk_ui_select_v4` | 予約名（DLL が認識する、15 文字）。直接は呼ばない。 |
| `hk_ui_page_v4` | DLL がないときの代わりの一覧（1 ページ 8 人）。直接は呼ばない。 |
| `hk_ui_example_v4` | 呼び出し例（自勢力から 1 人選ぶ）。 |

3 つのイベントは `claude_gen_unit_table_v4.py` で生成します（CP932・CRLF）。生成物は `claude_dat_ui_v4_select.dat` です。

## 2. 入力（呼ぶ前に DAT が用意する）

| 変数 | 必須 | 内容 |
|---|---|---|
| `@hk_ui_candidates` | ○ | 候補のユニット ID のリスト。並び順がそのまま「元の順」になる。`storeUnitOfPower` / `storeUnitOfSpot` / `storeRoamUnitOfSpot` / `storePlayerUnit` などの結果をそのまま入れる。 |
| `@hk_ui_columns` | | 表示列。1 要素が `見出し=能力名`。最大 8 列。 |
| `@hk_ui_title` | | 一覧の上に出す題名（1 要素）。 |
| `@hk_ui_sort` | | 最初の並び。`[見出し]` または `[見出し, asc|desc]`。見出しは `@hk_ui_columns` のどれか。 |
| `hk_ui_required` | | 1 にすると、キャンセルしても選び直しになる（必須の選択を飛ばさない）。 |

能力名に使えるのは `level, hp, mp, attack, defense, magic, magdef, dext, speed, hprec, mprec, move` の 12 個です（`setStatus` / `pushStatus` と同じ名前）。
DAT独自の数値は、§10で追加した `見出し=@refs` で渡せます。§4に残る能力値一時書換えの例は旧方式の記録です。

`hk_ui_count` / `hk_ui_index` / `hk_ui_status` / `hk_ui_backend` / `hk_ui_before` / `hk_ui_after` / `hk_ui_anchor` / `@hk_ui_values` は `hk_ui_pick_unit` が設定します。DAT 側で触る必要はありません。

## 3. 出力

| 変数 | 内容 |
|---|---|
| `hk_ui_status` | 1 = 選んだ、2 = キャンセル、3 = 候補が 0 人または異常 |
| `@hk_ui_selected` | 選ばれたユニット ID（status=1 のときだけ）。 |
| `hk_ui_index` | `@hk_ui_candidates` の中の位置（0 始まり）。検索や並べ替えをしても、元のリストでの位置が返る。 |
| `hk_ui_backend` | 1 = DLL の一覧で選んだ、0 = ゲーム本来の選択肢で選んだ |

## 4. 例（水練教育の講師選択）

```
event choice_01_swim_teacher_v4 {
 clear(@hk_ui_candidates)
 storeUnitOfPower(@plap,@hk_ui_candidates)
 // 講師補正を magdef に書いてから一覧を出す（元の DAT と同じ手順）
 ...setStatus(@各講師,magdef,補正値)...
 clear(@hk_ui_columns)
 setv(@hk_ui_columns,講師補正=magdef)
 addv(@hk_ui_columns,Lv=level)
 clear(@hk_ui_title)
 setv(@hk_ui_title,講師を選んでください)
 clear(@hk_ui_sort)
 setv(@hk_ui_sort,講師補正)
 addv(@hk_ui_sort,desc)
 set(hk_ui_required,0)
 routine(hk_ui_pick_unit)
 if(hk_ui_status == 1) {
  setv(@eranda_chara,@hk_ui_selected)
 }
 routine(resetMagdef)
}
```

## 5. 画面での動き

1. ゲーム本来の選択肢「一覧から選ぶ / Cancel」が出る。
2. DLL があれば、その上に一覧ウィンドウが開く。名前・ID・指定した列が出る。
   - 検索欄: 名前か ID の一部で絞り込む。
   - 見出しクリック: 昇順 → 降順 → 元の順。
   - ダブルクリックか Enter で決定。Esc・右クリック・Cancel で一覧を閉じる。
3. 一覧で決定すると、DLL が結果を書き込み、ゲームの選択肢を閉じてイベントが続く。
4. 一覧を閉じた（キャンセルした）ときは何も書き込まない。ゲームの選択肢がそのまま残るので、もう一度「Cancel」を選ぶとキャンセル、「一覧から選ぶ」を選ぶと 8 人ずつのページ選択になる。
5. DLL がない、または DLL が要求を受け付けなかった（候補が 512 人を超える、知らない能力名、存在しないユニットなど）ときは、「一覧から選ぶ」で 8 人ずつのページ選択（次へ・戻る・Cancel）になる。黙って先へ進むことはない。

## 6. 導入と無効化

導入（テスト用コピーでのみ）:

1. `plugins\HakushinDatUiSelectorV4.dll` を置く。
2. `hakushin_plugins.conf` に 1 行書く（SHA-256 は DLL の実際の値）:
   `hakushin.dat.ui.selector|HakushinDatUiSelectorV4.dll|1|10|1||<sha256>`
   v3 の行と同じ ID なので、v3 の行と入れ替える。v4 の DLL は v3 の要求も処理する。
3. `a_default\script\` に `claude_dat_ui_v4_select.dat` を置く。

無効化: conf の該当行を消すか、DLL 名の直後にある第 3 フィールド（enabled）の `1` を `0` にする。DAT はそのままで、ゲーム本来の 8 人ずつの選択になる。

## 7. DLL が守ること

- 書き込むのは `hk_ui_index`・`hk_ui_backend`・`hk_ui_anchor` の 3 つだけ。
- 書き込む直前に、要求・ゲームの選択肢・候補の能力値をもう一度読み直し、表示したときと 1 バイトでも違えば何も書かない。
- 名前は、ゲーム本来の表示名関数を 1 回呼んで得る。関数の先頭バイトが想定と違う、またはユニットがまだ読み込まれていないときは呼ばず、ID を表示する。
- 新しい要求が来たら古い一覧は無効になる（v3 と v4 の間でも同じ）。

### 分かった注意点

- ゲームは DirectInput でマウスを読むため、ゲーム窓を無効化しても、一覧の上のクリックが下にあるゲームの選択肢にも届く（実機で発生。DLL は書き込まず、ページ選択に切り替わった）。対策として、画面に余裕があれば一覧をゲーム窓の横に出す。余裕がない（全画面など）ときは中央に重ねるので、キーボード（↑↓・Enter・Esc）で操作するのが安全。
- 自動 arm は、ゲームの読み込みが終わった後に監視が始まる場合がある。読み込み中を一度も見なかったときは、タイトル画面が 10 秒続いたら arm する。
- 未確認: ゲームの選択肢を右クリックしたときの戻り値（0 以外ならキャンセル扱い）。

## 9. キャラチップ・ステータスパネル・教育のキャラ選択（2026-10-28 追加、§92）

### キャラチップ
- 各行の左にユニットのキャラチップを出す。
- チップ名はゲーム本来の決定処理（0x584970）で決める。image / sub_image / tkool の設定を含めて、ゲームが描くのと同じ名前になる。
- 画像は `a_default\chip`、なければ `chip2` から読み、32×32 に収めて表示する。縦横比は保ち、拡大はせず、枚数分けもしない。
- 見つからないときは、チップなしで表示する。

### ステータスパネル
- 一覧で行を選ぶと、ゲーム本来のユニット詳細画面がゲーム画面の右上に開く。Work のプレビューと同じ部品・同じ位置。
- 別の行を選ぶと、その人物に切り替わる。
- 決定・キャンセル・別の要求・一覧を閉じたときは必ず閉じる。決定のときは、パネルを閉じてから結果を書き込む。閉じられなければ書き込まない。

### 教育のキャラ選択（lecture.dat の choiceUnitFromList）
- `claude_lecture_v4.dat` の `choiceUnitFromList_v4` が、元の 8 人ずつのページ選択の代わりになる。入力（`@chara_list`）・出力（`@eranda_chara`、取りやめなら `yappa_yameru=1`）は元と同じ。
- 列は 補正(magdef)・Lv・HP・攻撃・防御・魔力・技術・速さ。「元の順」は元の DAT が並べた順。
- 有効にするには、`claude_patch_lecture_v4.py 元のlecture.dat 出力先` で lecture.dat の**コピー**を作る。元の `choiceUnitFromList` は `choiceUnitFromList_orig` に名前が変わって残り、新しい `choiceUnitFromList` が v4 版を呼ぶ。
- 元に戻すには、元の lecture.dat に置き換える。
- `claude_lecture_v4.dat` と `claude_dat_ui_v4_select.dat` の両方を script フォルダに置く。

## 10. DAT独自数値列（Work 2026-10-29、reader合成検証済み・実DAT未確認）

新しい列指定は **見出し=@refs** です。@refs は「候補順に並べた数値変数名」の文字列リストです。式、数値そのもののリスト、全員共通の単一変数ではありません。ゲームルール・補正・成功予想の計算と候補の選別はDATの責務で、DLLは計算済みの値を読むだけです。既存能力値を一時的に書き換える必要はありません。

| 入力例 | 意味 |
|---|---|
| HP=hp | 従来のユニット能力値列。互換性を維持。 |
| 講師補正=@teacher_scores | @teacher_scores の各要素を数値変数名として解決。 |
| @hk_ui_candidates = [akys, kmr] | 行の元順。 |
| @teacher_scores = [teacher_score_0, teacher_score_1] | 行0と行1に対応する変数名。 |
| teacher_score_0=30 / teacher_score_1=-5 | 表示・並べ替えに使う計算済みの値。 |

上表はデータ対応を示す表記です。見出し=@refs が実DATの字句解析でそのまま保存されることと、教育DATへの組込みは別途実機確認します。§4のmagdef一時書換え例は旧方式の記録であり、新規の独自列には本方式を優先します。既存教育DATの一時書換えや復元処理は、このreader追加だけで自動的には除去されません。

### 契約と上限

- 候補は1〜512行。能力値列と独自数値列を合わせて最大8列。所在地の補助表示列はこの8列を消費しません。
- 各@refsの要素数は候補数と同じ。候補と参照リストを独立に並べ替えてはいけません。DLLで表示順を変えても返るindexは元の候補順です。
- 同じ変数を複数行・複数列から参照して構いません。読取り要求は重複をまとめます。同じrefsリストを別の見出しで再利用することもできます。
- 値は符号付き32bit整数（INT32_MIN〜INT32_MAX）。成功予想の文字列を直接渡す列ではありません。必要ならDAT側で定義した数値の段階を渡し、文字列表現の追加は別仕様とします。
- 文字列上限はCP932の64バイト（終端を除く）。列指定は見出し=@refs全体もこの上限以内。見出しは重複不可です。
- refsリスト名・参照先変数名ではhk_ui_接頭辞をプロトコル予約名として拒否します。空名、制御文字、空白、ASCIIの@・=・,・DELも拒否します。式として評価せず、完全一致で既存変数を検索します。
- CP932の2バイト文字は境界を確認します。例えば「ァ」の後続バイト0x40をASCIIの@として拒否しません。切れた先頭バイト、不正な後続バイトは拒否します。これは文字コードの全割当を検証するUnicodeデコーダではありません。
- v4専用collectorは最大4096個の独自参照＋7個の出力、計4103キーを扱います。数値mapは16384ノードまで。循環・共有子・件数・ヘッダー再読取りの確認を維持し、v3の255キー制限は変更しません。
- @hk_ui_valuesは従来のv4どおり空または未定義。任意のrefsリストや数値変数は呼出し側DATが管理し、次の呼出し前に候補と一緒に作り直します。

### 不正・更新時の扱い

- 参照リスト／数値変数がない、人数不一致、未知ユニット、不正な列指定などは要求を拒否します。ゼロで補完せず、変数を新規作成しません。
- 出力7変数への参照を名前だけでなくセルアドレスでも拒否します。出力同士の同一セル参照も拒否します。
- snapshotには列の種類、refsリスト名、候補順の変数名、セルアドレス、値を保持します。二度の取得で一致することを確認し、確定前の再取得でも表示時と一致しなければ確定しません。同じ数値の別変数に差し替わった場合も検出します。
- 二度の取得は原子的な読取りではなく、同じ値へ戻るABAまで防ぐものではありません。既存のUIスレッド・要求番号・寿命確認は引き続き必要です。
- 不正な独自列や非対応の古いDLLでは、元の2択アンカーからDATのページ選択へ戻ります。ページ選択が独自数値列も表示する保証はありません。
- 計算／選択条件を変更せず、DLLからDAT式や任意のゲーム関数を実行しません。

### 所在地列の区別

現在準備している所在地列は、取得できた場所の内部IDを「ID: ...」として示す補助列です。表示用の地名を返す関数は未確認であり、内部IDを正式な地名として扱いません。取得不能は「未取得」で、放浪と推測しません。全8数値列との併用を維持します。
