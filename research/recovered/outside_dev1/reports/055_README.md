# 一覧をすぐ出す修正（Claude 2026-10-31、ユーザー判断）

## 判断
ユーザー: 「手を止めて 5 秒間表が出てこないのは遅すぎる。連打中に表が出て間違えてクリックしても問題ない」。
→ 入力保護（クリックが下の原作選択肢に届かないようにする捕捉）が整うのを待たず、要求から 0.25 秒で表を出す。

## 変更
- core/hakushin_input_session.{h,c}: `hkis_set_show_grace(session, ms)` を追加。0（既定）は従来どおり「保護が整うまで出さない」。0 以外なら、要求から ms 経過後、前面・要求の新しさ・世代が正しく、期限（5 秒）内であれば、保護が未完了でも表示を許可する。DLL 専用マウスの準備（prepare）の成否も問わない。
- 保護は裏で整え続け、整えばそれ以降のクリックは原作に届かない。表を閉じるときは従来どおり終了する。
- core/dat_ui_input_provider.h: 猶予 250 ms を設定。あわせて診断の記録（act_trace_20261031 と同じ。読むだけ）を含む。
- core/test_input_session.c: 猶予の試験を追加（前面・新しさ・世代の必須、準備失敗でも表示、既存の保護の引き継ぎと終了、期限切れは出さない、準備済みなら即表示）。既存の期待値は変更なし。

## 受け入れたリスク
- 表が出た直後、保護が整う前のクリックは原作に届きうる。下の原作選択肢（「一覧から選ぶ」・Cancel）が押されると、表は「要求が古い」として閉じる（既存の仕組み）。教育の取消は費用なし（実機確認済み）。
