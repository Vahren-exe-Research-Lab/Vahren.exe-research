# Display-only selector Core research adapter

`hakushin.selector.preview` wraps the unchanged `work_unit_selector_bridge.c` installer. Build with `./build_selector_plugin.ps1`; add `-Test` for isolated synthetic-host tests. Output: `selector_adapter_fixture/HakushinSelectorPlugin.dll` (x86). The build defines preview, native-stats, and native-location only. It never defines `WORK_SELECTOR_ENABLE_COMMIT`.

Core reserves host base + 0x1E7E3, length 5, before scheduling installation. The bridge independently checks its exact executable SHA-256 and expected `E8 28 01 00 00` bytes. Reservation is cooperative ownership, not an active patch or thread-quiescence guarantee. An overlapping Core owner causes clean refusal before installation.

Init pins the module before creating deferred callbacks. A worker polls for one visible, captioned, unowned, non-tool top-level host-instance window. A thread-specific message hook rechecks uniqueness and identity before claiming installation on that UI thread. The hook-owner worker stays alive until the callback claims installation, with a 600 x 100 ms polling budget (approximately 60 seconds plus API execution time). Timeout refuses subsequent pending installation; an installer already claimed may finish. Negative hook codes are forwarded without interpreting their payload.

Pending, installing, active, and failed-retained states refuse shutdown with BUSY. Reservations and a pinned module remain after installation or worker-start failure. There is no hot reload, unload proof, or quiescence guarantee. Failed retained states require process exit; do not retry installation in the same process. Core's existing ownership logic keeps its plugin record on failed init with retained reservations.

The tests use synthetic executables and a stub installer, plus the production DLL in an unsupported synthetic host. They check API errors, negative hook forwarding, reservation overlap, init on a non-UI thread, ignored message-only/hidden/ambiguous windows, one installation on the actual fixture UI thread, installer failure, worker-creation failure, and retained shutdown. The real installer rejects the synthetic executable and leaves its generation CALL bytes unchanged. These tests never attach to, patch, or launch the game.

## Optional synchronous skill hover (research, default off)

`WORK_SELECTOR_NATIVE_HOVER=1` queries Core managed CALL extension 3/version 1 during plugin init. After the bridge and optional render setup succeed on the selected UI thread, it passes that bound API to `WorkSelectorHover_Install`. The managed installer owns the CALL reservation; it must not be separately reserved as metadata. An unavailable or incompatible API rejects initialization before reserving/patching; a later install failure is retained until process exit.

Build without deployment using `./build_selector_hover_research.ps1`. The artifact is `../tests/HakushinSelectorPlugin-hover-research.dll`; this script does not copy it to the game. Run `./test_selector_hover_adapter.ps1` and `../tests/run_work_selector_hover_host.ps1` for scoped verification. Root reruns and hashes are in `../tests/work_selector_hover_integration_receipt_20261026.json`.

Current limitation: UI-thread scheduling alone is not proof that no other thread can execute the five-byte CALL being replaced. Establish the installation boundary before live enablement. Native game geometry, skill-tooltip display and cancellation still need live checks. Face, ability and movement-type hover remain outside the current skill-only handler.

## Claude addendum (2026-10-26)

Installation boundary: init captures a real handle to its own (loader) thread with HKLW_Capture(). Once the unique UI window is found on a different thread, the route worker waits for the loader thread to exit before installing the message hook, then rescans (diagnostics: route_wait_init_thread, route_init_thread_exited). Synchronous loading (same thread) proceeds immediately. The polling budget is not consumed by that wait. Window discovery still requires one eligible top-level window; after timeout, retry requires a process restart.

Optional build flag WORK_SELECTOR_PTR_MANAGED (with WORK_SELECTOR_HIDE_NATIVE_CHOOSER): the 0x238238 chooser pointer is installed through Core PTR_PATCH instead of a local VirtualProtect+CAS, and only the 0x1E7E3 CALL span is reserved manually. Core then refuses unload while the pointer is active.
