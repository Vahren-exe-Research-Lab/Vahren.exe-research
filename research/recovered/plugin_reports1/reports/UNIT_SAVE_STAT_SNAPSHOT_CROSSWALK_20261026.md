# 迫真戦記ver0.67：Unit保存値とDAT変更の不反映（2026-10-26）

- 研究ID `AUD-UNIT-SAVE-20261026-01`（既存T011/T014のクロス照合のみ、新規Task完了として数えない）。
- 分類：STATIC VERIFIED / USER OBSERVATION / RUNTIME GOLDEN NOT RUN。
- ユーザー観測：DATのユニット設定を途中で変えても既存ユニットの能力値は変化せず、新規雇用等で初めて反映される。
- 本件はユーザー観測を研究対象に記録したものであり、同一セーブでDATを差し替えた実機A/B再現検証は行っていない。

## 保存済み原作EXEの解析根拠
- `0x0058B7F0`：Unitの初期レベルを決定し、Unit+0x178..+0x1A0の11個の能力フィールドに定義から算出した整数値を直接代入。擬似Cに `**(int**)((int)local_84 + index) = iVar6 * iStack_8c + iStack_d0` と類する式。
- `0x00582D90`：Unit定義の `level` 取得後 `0x0058B7F0` を呼び、後続で `0x0058AFA0` 等を呼ぶ。既存T011生成研究と整合。
- `0x004667B0`：別のUnit初期化経路。`0x0058B7F0` と `0x0058AFA0` を呼び出す。
- `0x0058EFD0`：Unitの各種数値を保存。+0x168/+0x16C/+0x170の進行値と、+0x178～+0x1A0の11個の能力値の実数値を個別に書き込む。
- `0x0058E870`：保存されたUnit数値をそれぞれ読み込み、+0x178～+0x1A0へ直接復元。関数内に `0x0058B7F0` の直接CALLなし。
- `0x0058A650`：EXP閾値到達時にレベルを増加させ、対応する11個の現在値へ成長分を加算。全員を毎ターンDAT基準へ無条件リセットするものではない。
- Ghidra参照一覧：`0x0058E870`直接CALLはロード系の`0x0045E432`と`0x0045F841`。`0x0058B7F0`直接CALLはUnit生成や各特殊経路で見られるが、`0x0058E870`にはない。

## ゲーム互換性と編集ツールへの帰結
- 原作互換で保存された既存Unitはロード時のスナップショット能力値を保持する。新DATの基礎能力値を参照するのは生成・再生成・成長などの特定処理。
- DAT変更の既存ユニットへの一括反映機能を作るなら、対象Unit全員の保存/実行時の値を更新する追加処理が必要。
- 既存の成長、個体差、装備、イベント補正があるため「DAT値で全上書き」は損失が発生し得る。再生成・差分補正・選択的更新を分けて設計。
- レベルアップでは既存値への加算があるため「既存は永久に全能力不変」とは言わない。
- 未解決：全11フィールドの表示名との厳密照合、どの補正が永続化されるか、クラスチェンジ/変身/復活での再初期化条件、全ロード後の派生キャッシュ更新。
