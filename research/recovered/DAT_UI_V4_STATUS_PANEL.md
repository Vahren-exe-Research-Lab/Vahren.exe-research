# v4 一覧のステータスパネル：ボタンなし表示と説明表示（設計、2026-10-29 Claude）

DAT 汎用一覧（v4）で行を選ぶと、ゲーム本来の一時詳細パネル（TempStatusWnd、0x8BCD48）が開く。このとき自勢力ユニットには雇用・解雇などのボタンが付き、押すと実際に解雇などが起きてしまう。本書は、これを**ボタンなし**で表示する方法の設計。あわせて、説明表示（ホバー）の現状をまとめる。

確かさ: 実機確認／静的確認／テストのみ／推定。アドレスは VA（0x400000 基準）。

## 1. 分かったこと（静的確認、§95）

### ボタンの仕組み
1. パネルの組み立て（0x55BC60）は、条件を満たすボタンの枠と文字を、パネルの画像に**描くだけ**（0x455520 を 6 か所で呼ぶ）。描いたら印を立てる（+0x1C4 雇用、+0x1C5 召上げ、+0x1C6 解雇、+0x1C7 アイテム）。
   - 0x455520 の呼び出し位置: 0x55D77F、0x55D7C6、0x55D951、0x55D976、0x55D9AF、0x55D9F0（すべて 0x55BC60 の中）。
   - 0x455520 の呼び方: EAX=ウィンドウ、ESI=矩形、スタックに (描画先, 文字)、`ret 8`。EBX・EBP・EDI・ESI は保存される。呼び出し元は戻り値を使わない。
2. 矩形は全パネル共通のグローバル: 0x68B578（雇用/召上げ）、0x68B568（解雇）、0x68B588（アイテム）。ポインタ表 0x65BEA8。
3. マウス押下（仮想関数 15 = 0x560650）:
   - +0x1BC（押下中の番号）が「なし」（0x80000008）でなければ、1 を返して終わる。
   - 出撃準備中（WarWnd 表示中）なら 0 を返す。
   - 印が全部 0 なら 0 を返す（何もしない）。
   - 印のどれかが立っていれば 3 つの矩形を当たり判定し、当たった番号の印が立っていれば +0x1BC に番号を入れる。
4. マウスを離す（16 = 0x560CA0）:
   - +0x1BC が「なし」なら 0 を返す（何もしない）。
   - 番号が入っていれば「なし」に戻し、離した位置が同じ矩形の中なら、**印を確認し直さずに**その番号の動作（雇用画面・解雇・アイテム）を実行する。
5. TempStatusWnd の仮想関数表は 0x639CD4。押下は +0x3C（0x639D10）= 0x560650、離すは +0x40（0x639D14）= 0x560CA0。StatusWnd（0x639C5C）と同じ関数を指しているが、表は別なので、**TempStatusWnd の表だけを書き換えられる**。

### 結論
- 「印だけ消す」は、押下より後で消すと、すでに入った +0x1BC で動作してしまう（Codex の指摘どおり）。
- 押下の**前に**「印を 0、+0x1BC をなし」にすれば、押下は何もせず、離しても何もしない。これは他勢力のユニットのパネルと同じ状態。
- 見た目（ボタンの枠と文字）は組み立て時に描かれるので、描く処理も止める必要がある。

## 2. 設計（モード 1: ボタンなし、DLL がパネルを使っている間だけ）

「DLL が使っている間」= v4 一覧が TempStatusWnd を開いて、閉じるまで（既存の `v4_detail.owned`）。それ以外の時間は何も変えない（ゲームが TempStatusWnd を使う場面には影響しない）。

### A. 描かない（見た目を消す）
- 0x455520 を呼ぶ 6 か所の CALL（E8 rel32）を、DLL の小さな関数へ向け直す（Core の CALL 差し替えを使う。差し替え前に、元の 5 バイトが `E8` と 0x455520 への相対値であることを確かめる）。
- DLL の関数: `EAX == 0x8BCD48`（TempStatusWnd）かつ owned なら、何も描かずに `ret 8`。それ以外は 0x455520 へそのまま跳ぶ（レジスタを変えない）。
- 印は組み立てのたびに立つが、B で無害にする。

### B. 押しても動かない（安全）
- TempStatusWnd の仮想関数表の +0x3C（押下）と +0x40（離す）を、DLL の関数に差し替える（Core の ptr_patch。差し替え前に元の値 0x560650 / 0x560CA0 を確かめる）。
- DLL の関数（thiscall、引数 3 個、`ret 0xC`）: `ECX == 0x8BCD48` かつ owned なら、+0x1C4〜+0x1C7 を 0、+0x1BC を 0x80000008 にしてから、元の関数を呼ぶ。owned でなければ、そのまま元の関数を呼ぶ。
- 結果: 押下は印が全部 0 なので何もせず 0 を返す。離すも +0x1BC が「なし」なので何もしない。
- B だけでも安全性は保たれる（A は見た目のため）。A の差し替えに失敗したら、ボタンは描かれるが押しても動かない、という状態で動き続ける。B に失敗したら、パネルを開かない（v4 は名前と数値の一覧だけで動く）。

### やらないこと（理由）
- WarWnd の表示中フラグ（0x8BA5BC）を立てる: ゲーム中の約 30 か所の動きが変わる。
- 勢力の +0x1D やユニットの +0x74/+0x7A を書き換える: ゲームの状態を変える。
- StatusWnd の表（0x639C5C）を書き換える: 本来の詳細パネル（ボタンあり）まで変わる。
- 組み立て後に印を消すだけ: 上の結論のとおり不十分。

## 3. 試験

- 偽の TempStatusWnd（0x200 バイト以上）と偽の表で、owned のとき押下前に印と +0x1BC が消えること、owned でないとき何も変えないこと。
- 6 か所の CALL の差し替えと戻し（元のバイト列の確認、失敗時に戻ること）。
- 表の差し替えと戻し（DLL を閉じたら元に戻る、二重に差し替えない）。

## 4. 説明表示（ホバー）について

- TempStatusWnd の表の説明表示（+0x44）は空の関数 0x406E20、StatusWnd は 0x561120（静的確認）。
- イベント実行中は、プレイヤーの処理（0x521560）が、仮想関数 +0x1C が真のウィンドウにしか説明表示を渡さない。StatusWnd・TempStatusWnd とも +0x1C は常に偽（0x43B5A0）。元のゲームでもイベント中は説明が出ない（ユーザー確認、§93.4）。
- したがって説明表示は**元のゲームにない機能の追加**になる。Codex が作業中の方法（0x521AF0 の呼び出しを差し替えて、DLL が説明表示を直接呼ぶ）と、本書の B と同じ「TempStatusWnd の表を owned の間だけ差し替える」方法のどちらが安全かは、Codex の試験結果と合わせて決める。
  - 表を使う場合の候補: +0x44 を 0x561120 に、+0x1C を真を返す関数に。ただし +0x1C が真になると、イベント中に TempStatusWnd へ他の入力も渡る可能性があるので、0x521560 の中で +0x1C を見ている箇所をすべて確認してから。（未確認）

## 5. Codex の hk_ui_detail 案との対応

- 0 = パネルを出さない、1 = ボタンなし（本書の A+B、既定）、2 = ゲーム本来のボタンあり（明示したときだけ。A・B を適用しない）。
- 2 は、一覧の途中で解雇などが実行されうるので、DAT 側が明示したときだけ使う。
