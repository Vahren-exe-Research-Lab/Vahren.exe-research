# 加工前後の識別差によるPR照合の点検

固定版の全1,839受入行について、加工前と保存版のGit blob identityを区別した。完全一致版は受入済み保存バイトだけから算出し、元文書を読み直していない。加工版のローカル原本78パスだけは、本文を表示・再レビューせず現SHAを照合し、78件すべてが既受入の出典SHAと一致した。[78件の例外照合票](SOURCE_IDENTITIES.tsv)にそのGit blob・サイズ・mtimeと保存版の識別を残す。部分版3件は元資料を展開せず[未証明表](UNPROVEN_OR_PARTIAL_SOURCE_IDENTITIES.tsv)へ分けた。

今回、加工前原文だけがPRに追加で一致するケースは**0件**だった。したがって未回収キューを減らしたり、新規研究・採録件数を増やしたりしていない。新しい全文取得や原文公開はなく、既存の[保存版とPRの完全一致表](../github_reconcile2/GITHUB_EXACT_BODY_LINKS.tsv)を引き続き使える。全行の機械的な再掲は重複となるため公開表は例外78件と未証明3件へ絞り、私用計算結果のハッシュと集計をSUMMARY.jsonへ残した。

原文一致は保存された加工版や部分版を全文原本へ昇格させず、意味・実機・現在のPC全体・未保存原本の存在を証明しない。PR blob自体は取得しておらず、原本の私有情報を保存・復元・公開していない。保留解除・原本削除の根拠でもない。
