# ON-STAND-013｜戦闘中の技能奪取・付与とユニット情報パネルの同期
記録日: 2026-10-26 JST ／状態: UI仕様案・原作命令の静的/文書照合、戦闘実機表示NOT VERIFIED。

## ユーザーの問い／推奨するUI要件
- [USER_QUERY] 奪取/付与でユニット情報パネルの技能表示が増減するか。
- [PROPOSED / ACCEPTANCE-PENDING] 戦闘中に選択・ホバーしたユニットの情報パネル、および操作用スキルアイコンは、その戦闘で現在使用可能な技能のリストを表示する。
- [PROPOSED] 奪われた側ではスキルアイコンが消え、操作/AIから使えなくなる。受領側では同じアイコンが追加され、実際に使用/自動召喚できる。
- [PROPOSED] 開いたままのパネルも変更直後に追従して再描画する。描画キャッシュが残るなら安全な再表示処理だけを検討し、原本の関数フックや全画面再構築を最初から前提としない。
- [PROPOSED] 追加された技能は元のスキルアイコンを使用。既存の _add.png オーバーレイを利用できる場合には付与技能と分かるようにする。
- [USER_FIXED] 技能奪取/付与は戦闘限り。戦略側の恒久所持技能や次回戦闘のスキル一覧を変更してはいけない。

## 表示状態の契約（PROPOSED）
| 段階 | 元の使い手の表示 | 受領者の表示 | 備考 |
|---|---|---|---|
| 戦闘開始 | 元のスタンド召喚技能あり | 受領前の技能のみ | スタンドは開幕自動召喚 |
| 奪取発動 | 元の召喚技能が消える | 受領前のまま | 消滅させるスタンドも同時処理 |
| DISC保管中 | スキルなし | スキルなし | 奪い手が保管しているだけ |
| 受領者へ付与 | 元の召喚技能なし | 付与された召喚技能あり | 受領者が自動召喚、HP/Rは受領者基準 |
| 戦闘終了 | 恒久所持技能のまま | 一時貸与技能なし | 戦略画面に残存させない |

## 追加で確定した戦略/戦闘の命令差（2026-10-26 / ON-STAND-014）
- addSkill は戦略側で取得して残る技能に使われる（unit構造体のWikiには転職後も残るとある）。
- removeSkill は戦闘中のスキル削除専用としてWikiに記載される。
- 原作の Ai戦闘制御_軍楽隊なし版.dat L1155-1161 が、ONDISKの sp_ondisk を戦闘用に removeSkill し、別技能を addSkill→eraseSkill で差し替えている。つまり戦闘中の一時技能変更のDAT既存パターンがある。
- したがって技能の戦闘限定化自体は重要な難所ではない。情報パネルの自動再描画はこれとは独立した未検証問題。
- 詳細：SKILL_BATTLE_SCOPE_NATIVE_DAT_20261026.md。受領者の元技能をeraseSkillで誤削除しない条件分岐が必須。

## 原作の命令と技術上の留保
- 公開Wiki: removeSkill(unit,skill) は戦闘中の技能削除。addSkill(unit,skill)、addSkill2 はスキルリストへの追加。
- 公開Wiki: eraseSkill(unit,skill) は所持技能からの消去。removeSkillとeraseSkillの戦略/戦闘範囲を混同しない。
- 迫真原作: Ai戦闘制御_軍楽隊なし版.dat 551-591行は、s_inyume/s_toshinoを removeSkill し、COM派生技能を addSkill→eraseSkill で戦闘中に差替える実例。
- 公開Wiki: skillアイコンに付与型 _add.png オーバーレイがある。ただしこれだけでは戦闘UIの再描画が自動かを証明しない。
- 公開Wiki: reloadMenu(on) は勢力メニューの再表示用。戦闘中の情報パネル刷新に使えると考えない。
- 既存Ghidra V9: removeSkill/addSkill/eraseSkillの文字列は FUN_004A6E40 のscript command dispatch内で参照確認。戦闘パネル描画とこれらのコマンドの同時更新は未追跡。
- PEER_SCRIPT01_RTTI_CLASSES_20261011.md では BattleStatusWnd と StatusWnd/TempStatusWnd の異なるWindows UIクラスを記録。どのウィンドウが戦闘中の技能一覧を更新するかは未確定。

## 実機確認の最低条件
1. 隔離した原作コピーで、戦闘開始時のONDISK技能欄・操作スキル欄を記録。
2. DATの戦闘イベントで既知スキルを removeSkill して、情報パネルを開いたまま/開き直したときの双方の表示を確認する。
3. 別の人材へ addSkill した瞬間と選択し直した後を比較。表示が増えてもスキルが使えない、使用できても表示にない、といったUIと実体の不一致を記録。
4. CPU側のCOM派生技能がある場合、根元だけ削除した場合と派生一式を削除した場合を比較し、表示と実発動が一致するか確認する。
5. 戦闘終了・次の戦闘・セーブ再ロード後に、元技能だけが所持技能へ戻ることを確認する。
6. パネル表示更新に特別な処理が必要な場合は、描画キャッシュと選択状態の寿命を確認して必要最小限で更新する。
