# STAND-001｜スタンド戦闘ルール・実装仕様
## ユーザー確定
1. スタンドは召喚者（スタンド使い）の位置を中心とする半径Rを越えて移動できない。
2. [USER_FIXED / 2026-10-25] **スタンドには普通の人間の物理攻撃が通用しない**。スタンド自身のパンチ・斬撃は物理攻撃として使用可能であり、**その攻撃は敵スタンドにも有効**。旧『スタンド自身は物理攻撃できない』の解釈は完全撤回。
3. 召喚者とスタンドは体力を同期し、スタンド側／召喚者側のいずれがダメージを受けても共有する。
## 2026-10-26 制作方針とルールの優先順位

[USER_FIXED] **一般の召喚トークンは、重複して複数体存在することを許容**。召喚者/元技能別の完全な個体追跡や、重複を必ずゼロにする機能を製品完成の必須要件にしない。TNOKのチコリータを技能奪取と同時に消滅させたいという従来の希望は残すが、**一般召喚の一意性は厳格な検収基準にしない**。無関係の部隊まで巻き込んで削除する危険な近似実装は採用しない。

[USER_FIXED] **スタンドは別枠で厳密に管理**。既存DATの召喚・攻撃・耐性・衛星追従を最大限利用し、DATのみでは保証できない不変条件だけ最小の戦闘アダプタで補う。原作には Unit+0x178～0x180 の親→子ベクタがあるので独自親子台帳を作り直さない。

### 具体的な状態遷移（実装契約、PROPOSED）

1. BATTLE_START：元の使い手に召喚権があれば、一回だけスタンド生成。Unit間の親子ベクタと戦闘中の技能権限を利用。
2. ACTIVE：AI追従は `satellite`、位置と距離Rのハード制約は別レイヤー。HP正本は**現在の術者Unit**のみ。
3. STOLEN：まず元使い手の戦闘用技能権限を一時停止、既存のスタンドを消去する。再出現の待機召喚も無効化する。
4. DISC_HELD：スタンドは存在しない。任意の味方への付与待ち。
5. TRANSFERRED：受領者へ技能を付与し、同じ召喚スキルを受領者から発動。新しい親UnitとHPを採用し、旧術者のHPをコピーしない。
6. BATTLE_END：一時技能付与・封印とスタンドを終了。恒久技能・学習設定・セーブ情報には影響させない。

### 実装時の提案と未決事項（まだUSER_FIXEDではない）

- [PROPOSED] 1回の範囲攻撃が親子両方に命中した場合は同一ヒットIDを重複計上しない。別の攻撃は各々加算する。ゲームバランス試験後に採否判断。
- [PROPOSED] 親が死亡すればスタンドを即消滅。共有HPが0なら親も死亡（独立Python試作準拠）。
- [UNDECIDED] 一般魔法・状態異常のスタンドへの効き方。現時点で一般物理無効以外を勝手に免疫扱いしない。
- [UNDECIDED] スタンド射程Rの具体値と、壁・ワープ・ノックバック・プレイヤー操作時の境界処理。
- [UNVERIFIED] 原作DATだけでハードR、同一HPプール、奪取直後の保留中召喚の無効化を満たせるか。静的検査成功は原作実機合格ではない。

### テスト優先度
- **P0（スタンドのみ厳格）**：初回自動召喚、常時射程R、親子双方向HP同期、通常物理0/スタンド物理有効、親死亡/子死亡、奪取時に消滅、受領者から再召喚・再リンク、戦闘終了リセット。
- **P1（DAT連携）**：召喚上限、NPC AI、技能再取得、元技能と新技能の衝突、セーブ互換。
- **P2（一般召喚の品質改善）**：TNOKの個体別消去・重複整理・全技への無改変対応。現段階では完成ブロッカーにしない。

## 2026-10-26 ON-020｜召喚トークンの種別によるDISC奪取ルール
- [USER_FIXED] **固有型**（チコリータ系・スタンド）：同じ種類を全消ししてよい。特にスタンドは奪取時の即消滅がP0。固有型の一括削除は`removeTroop`のゲーム挙動を検証した後にのみ実装。
- [USER_FIXED] **量産型**（いんゆめくん、ALC役クッキー☆声優の歳納人形）：同名の召喚物が多く、無関係な個体まで消す全消去は不適切。
- [PROPOSED] 量産型を奪う際は本人の召喚技能を封印し、戦場に既にいる召喚物はそのまま戦闘させる。CPUの`s_inyume_com0/1/2`と`s_toshino_com0/1/2`も全て封印し、さらなる追加召喚を止める。通常トークンの重複は許容、絶対個体所有追跡はP2。
- [SAFE DEFAULT] 未知の召喚技能に対しては名前による大量削除をしない。スタンドHP共有・絶対射程・一般物理無効/スタンド物理攻撃・戦闘限定移譲は一切緩めない。
- [EVIDENCE] F20_summon.datの`class inyume { member=inyume*7 }`、`class toshino { member=toshino*7 }`。20_クラスの`class a01a`は原作で「ALC役クッキー☆声優」。詳細は`SUMMON_DISC_REMOVAL_POLICY_20261026.md`。この戦略はDAT/エンジン実機での動作未検証。

### ON-021：単体型／量産型はスキル定義で固定判定（2026-10-26）
- [USER_FIXED] 単体召喚型のスタンド／チコリータ系は、戦場に同名が複数いても消滅を行う。
- [USER_FIXED] 量産召喚型のいんゆめくん／歳納人形は、残数が1体だけでも既存個体を消滅させない。新規召喚技能（CPU派生含む）のみ封印。
- [PROPOSED / SAFE DEFAULT] 召喚技能が未分類の場合、個体数だけを見て一括消去せず、技能封印のみ行う。タイプの自動分類はDATの実在の`member`、`add/add2`、技能連鎖等を確認して行う。
- [VERIFICATION] 固有型の消去は`removeTroop`等の実機確認後。一括消去は**奪取の時点で一度だけ**実行し、後から受領者が新しく召喚したスタンドを誤って消さないようにする。

## 2026-10-26 ON-STAND-013｜戦闘中の情報パネルと技能増減（仕様案）
- [PROPOSED / USER_QUERY] DISC奪取時、元の使い手の**戦闘情報パネルと操作技能欄**で失った技能が消える。受領者のパネルでは付与されたスキルのアイコンが増え、自動召喚が発生する。戦闘終了後に元の技能構成へ戻る。
- [EXISTING] 原作の removeSkill/addSkill は戦闘中の技能削除/追加に対応。付与スキル用アイコン装飾 (_add.png) も存在。
- [UNVERIFIED] 既に開いている情報パネルが自動再描画されるかは未確認。戦略画面用reloadMenu(on)では解決しない。描画キャッシュ/操作欄は隔離した実機で検証する。
- 技能の使用可否、情報パネル、操作スキル欄の3箇所が一致することを品質条件とする（採否確認待ち）。詳細は SKILL_THEFT_UI_SYNC_SPEC_20261026.md。

## ON-STAND-014｜技能の戦闘中限定化と恒久スキルの区別（2026-10-26）
- 原作のremoveSkillは戦闘中の技能削除、addSkill/eraseSkillは所持技能変更。原作AIにremoveSkill＋addSkill→eraseSkillの戦闘限定差替えパターンが存在。DISC奪取/付与もこのパターンを優先利用（詳細 SKILL_BATTLE_SCOPE_NATIVE_DAT_20261026.md）。
- 受領者が既に同技能を持っていた場合、eraseSkillで元の恒久技能を消さないようにする。
- スタンドの消滅、HP共有、絶対射程、戦闘情報パネルのリアルタイム更新は「一時技能のDAT変更」と別問題。実機確認まで未完了。

## 試作での明示的な設計
- 正本HPは召喚者に一つだけ持ち、スタンドのHPは親HPのview。回復・ダメージとも反映し、最大値を超過しない。
- 1召喚者につき1スタンドを初期ルールとして実装（複数は未決）。
- 距離はX/Y座標上のユークリッド距離。Rは未指定なのでスタンドごと設定。
- 親が移動したときは子を親からR以内へ戻す。**壁/地形の障害処理は実ゲームの移動レイヤーが別途担当**。
- 子HPが0になれば親も死亡、親死亡では子を消す仮ルール。ゲームの死亡イベントは後段adapterで1回発火。
- 同一のダメージ事象IDが親と子に二重通知された場合は重複カウントしない試作。複数の独立攻撃は加算。
- `begin_tick(tick)`でフレーム/ティックごとに重複判定キャッシュをリセットし、長時間戦闘の無制限肥大化を防止する。
- スタンド自身の物理攻撃は可能。戦闘モデルでは通常の人間の拳・剣・銃などを `ordinary_physical`、スタンドによる拳などを `stand_physical` と分類。前者だけがスタンドに対し0ダメージ。攻撃者がスタンドかどうかで判別する `attack()` と `immune` の確認用receiptを導入。
- DAT本命は専用ユーザー攻撃属性 `standhit`。既存 `attribute.dat` の唯一の `attribute` ブロックに追加する必要がある。試作では原作本体未変更。
- スタンドの通常物理耐性は既存ゴーストを参考に `sw/pl/ch/ar/gn/cn` と `msw/mpl/mch/mar/mgn/mcn` へ各10。`standhit=5` で敵スタンドの物理打撃だけ有効にする。
- `skill on_stand_punch:sk_sw` は `str=attack*100`, `attr=standhit`。視覚と威力は拳による物理攻撃で、ダメージ耐性の判定だけ独立属性。スタンド以外の普通の人間にも有効。光・闇など超常攻撃がスタンドへ効くかは後日仕様決定。
