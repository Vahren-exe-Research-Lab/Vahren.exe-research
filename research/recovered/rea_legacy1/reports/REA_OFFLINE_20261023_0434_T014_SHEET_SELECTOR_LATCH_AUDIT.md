## 2. 増分A：原作のGameManager本体から選択器への実際のCALL

`0x00555CD0`内に次の隣接命令がある。

```asm
0x00555E35  B9 F0 E2 8B 00    MOV ECX, 0x008BE2F0
0x00555E3A  89 5D FC          MOV [EBP-4], EBX
0x00555E3D  E8 EE 3A F6 FF    CALL 0x004B9930
```

この区間にECXを変更する命令はない。よって、**このCALL経路では`0x004B9930`がGameManagerグローバルアドレス`0x008BE2F0`をthis/ECXとして受け取る**。SQLiteにも`0x00555E3D → 0x004B9930`の直接CALLがある。この受信者は以前の`0x00543428`が静的初期化時に参照したオブジェクトと**アドレスが一致する**。ただし時間的・動的に同一状態であることを保証するものではない。

## 3. 増分B：`GameManager+0x1EF144`が8分岐のセレクター

```asm
0x004B9970  MOV EAX, [ESI+0x1EF144]
0x004B9976  CMP EAX, 7
0x004B9979  JA  0x004B99DF
0x004B997B  JMP DWORD PTR [EAX*4+0x004B99FC]
```

`0x004B99FC`から8個の32ビット値を**原作PEの実ファイル**より直接取得し、各ケースのCALL相対アドレスとSQLiteの直接CALLを独立照合した。単なるGhidra疑似Cのswitch再掲ではない。

| モード値 | ジャンプ先 | その分岐の直接CALL先 |
|---:|---|---|
| 0 | `0x004B9982` | `0x0048AD30` |
| 1 | `0x004B99B9` | `0x0048C880` |
| **2** | **`0x004B99C7`** | **`0x0048D6A0`** |
| **3** | **`0x004B99DF`** | **分岐固有のCALLなし** |
| 4 | `0x004B998F` | `0x0048B4A0` |
| 5 | `0x004B99AB` | `0x0048BF60` |
| 6 | `0x004B999D` | `0x0048BC70` |
| 7 | `0x004B99D4` | `0x0048EA60` |

モード2は既存研究の戦闘移行関連関数`0x0048D6A0`へ向かう。ここでの**新規証拠は選択器の8ケース対応とGameManager受信者の結合**で、戦闘自体の実機Goldenや既存の戦闘入口発見を再計上しない。

**モード3は「完全無処理」ではない。** 対応エントリが共通継続点`0x004B99DF`を指すため、`0x004B99E0 CALL 0x004C24B0`と`0x004B99E5 CMP [ESI+8],2`による共通処理に進む。7より大きいモード値も共通継続点に入る。非終了なら`0x004B99E9 JNE 0x004B9970`で再選択する。値3を強制的に即returnする互換実装は機械語と異なる。

## 4. 増分C：画面遷移側からセレクターを書き換える経路

検索DBに保存済みの局所擬似Cと原作機械語を照合したところ、`+0x1EF144`への直接書込を行う関数は、対象オフセットのテキスト検索範囲では4件：`0x004B9AA0`、`0x005437B0`、`0x00543900`、`0x00543B10`。後者3件は対象処理内で`this+4`から取得した参照先の同オフセットに遷移先識別値を格納し、`+8=1`を立てる。`0x004B9AA0`はメッセージボックスで指定の戻り値6を受けた場合に選択器を**0へ戻す**。

代表：

```asm
0x005439D2  CMP EAX, 0x2710           ; 10000
0x005439D7  JGE 0x005439EC          ; >=10000ならセレクター書込を行わない
0x005439DC  MOV [EDX+0x1EF144], EAX ; 遷移先識別値
0x005439E5  MOV DWORD PTR [EAX+8],1 ; manager側通知
```

この経路は、遷移エフェクト側が一定条件でGameManagerの選択値を指定し、制御ループが関数を選択するという静的な連携を示す。**個々の呼出しが必ずこのグローバルGameManagerの実インスタンスへ到達するか**は、生成元の全caller・実行時オブジェクト同定が未完了のためVERIFY。

## 5. 増分D：別フィールド`+0x1EF150`による中断ラッチと巻戻し

`0x00543440`（sheet登録ラッパー）には次の実バイトがある。

```asm
0x00543445  CALL 0x005433D0
0x0054344D  MOV BYTE PTR [EAX+0x1EF150], 1
```

`0x00543900`内の中間段階の判定は次の通り。

```asm
0x00543966  CMP BYTE PTR [EDX+0x1EF150], 0
0x0054396D  JNE 0x00543959
0x00543959  DEC EAX
0x0054395A  MOV [ESI+0x1C], EAX
```

`JNE`は同じ経路内の進行カウンタ減算・保存へ飛んでreturnするため、**+0x1EF150が非ゼロなら、その条件が評価される時点で進行を一段戻して遷移を先送りする**ことが分かる。ただし直前のグローバル状態フラグ2種からも同じ巻戻し点へ分岐するため、上記は唯一の停止条件ではない。また`+0x1EF150`をどのタイミングで誰が解除するかは、隣接する別関数の書込候補を引き続き照合する必要がある。

**オフセットの役割を混同しない**: `+0x1EF144`は整数セレクター、`+0x1EF148`は前回の仮想CALL本体が読む独立した1バイトガード（書込元VERIFY）、`+0x1EF150`は遷移停止/先送り条件に使われる1バイト。名前は暫定的な研究上の分類であり原作C++型名ではない。
