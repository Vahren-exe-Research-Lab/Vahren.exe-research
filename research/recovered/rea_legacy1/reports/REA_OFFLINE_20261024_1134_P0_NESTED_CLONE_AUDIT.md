## 1. 増分①：再構築時、入力ノードの「値オブジェクトのアドレス」をコピー関数へ渡す

`0x0048F9E0` の `0x48FBCA MOV EAX,[ECX+4]`→`0x48FBCD MOV ECX,[EAX]` は入力木のヘッダと先頭ノードを取り出す。`0x48FBCF PUSH EAX`、`0x48FBD0 PUSH ECX`、`0x48FBD1 CALL 0x00498E60` へ続く。

`0x00498E60` の各反復では、**`0x498E73 LEA EAX,[ECX+0x0C]`** として、入力ノードのキー（`+0x0C`）と内側マップ（`+0x10`）が始まる**値領域のアドレス**を求める。`0x498E70 MOV EDX,[ESI+4]`、`0x498E77 LEA ECX,[ESP+4]`、`0x498E7B MOV EDX,ESI` を経て `0x498E7D CALL 0x00498F90`。ここでは**EAXが入力値領域、EDXが出力コンテナ、ECXが戻り先領域**、スタックに挿入ヒントを渡すという局所ABIが復元できる。全関数の例外ABIが確定したわけではない。

`0x00498F90` の初回分岐は `0x498F99 CMP DWORD PTR [EDI+8],0` で**出力コンテナの件数**を検査。出力が空なら `0x498FA8 CALL 0x004991C0` で新規ノードを作り、`0x498FB4 CALL 0x00476830`で挿入する。入力範囲が空なら `0x498E65 CMP ECX,[ESP+0x0C]`→`0x498E69 JE 0x498ED5` のためコピー自体を実施しない。

## 2. 増分②：外側キー値は32bitをそのままコピー／内側はノードを新規確保して再帰複製

`0x004991C0` は `0x4991EF PUSH 0x24` で**出力側の外側ノードを新規確保**。`0x49922D MOV ECX,[EBX]` → `0x499232 MOV [EAX],ECX` により、元ノード値領域先頭の**4バイトのキー値を改変せず出力側ノードの`+0x0C`へコピー**する。キー値が「参照先オブジェクトのポインタ」である先行経路の場合、**ポインタの値は保持**するが、参照先オブジェクトを複製する命令ではない。

続けて`0x49922F ADD EBX,4`と`0x499237 PUSH EBX` / `0x499238 PUSH EAX` / `0x499239 CALL 0x0047BA10` があり、外側ノードの`+0x10`から始まる内側マップをコピーする。`0x0047BA10`は`0x47BA40 PUSH 0x14`で新しい**内側マップヘッダ**を確保し、`0x47BA7B CALL 0x00476B20`へ進む。

`0x00476B20` は `0x476B31 CALL 0x00476B90` でソースのノード木を再帰コピーし、`0x476B39 MOV ECX,[EBX+8]`→`0x476B3F MOV [ESI+8],ECX`で**内側マップの要素数**を引き継ぐ。`0x00476B90`はソースが番兵（`+0x11 != 0`）でなければ、`0x476BCF LEA ECX,[EBX+0x0C]`→`0x476BD3 CALL 0x00565780`によって**新規の内側ノード**を確保し、その後 `0x476BFF`・`0x476C0D` で左右の子を再帰コピーする。ノード色は `0x476BE3`→`0x476BE6` で複写。

`0x00565780` 自身では `0x5657AF MOV EDX,[ESP+0x10]`、`0x5657B3 MOV EDX,[EDX]`、`0x5657B5 MOV [ECX],EDX`で**内側ノードの32bitキー値をそのままコピー**する。元の内側木ノードと複製先ノードは別のメモリ確保領域だが、**キーが指す先のオブジェクトは共有し得る**。つまり「コンテナノードの深いコピー」と「キーの参照先の深いコピー」は別物である。

これは先行の `0x00476C50` によるマップ**交換**とは別の処理。`0x0047BA10`→`0x00476B20`→`0x00476B90` は本件コピー専用の追加根拠であり、交換関数と混同しない。
