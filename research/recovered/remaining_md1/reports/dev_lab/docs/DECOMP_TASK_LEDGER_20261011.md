### 最上位のユーザー要求（v1.1で明示、v1.2で戦闘を最優先）

**目的は原作EXEの完全互換・元C++再現ではない。原作の「操作の基本挙動」「ダメージ計算」「戦闘CPUの判断」「戦略CPUの判断」「ゲームルールとバランス」を可能な限り厳密に再現し、現代的な新EXEで快適に遊べること。**

**v1.2最優先指示:** **通常戦闘モードを単独完成させる。** 通常戦闘画面・Unit移動・戦闘操作・全戦闘スキルの効果/視覚演出・原作ダメージ計算/状態異常・戦闘CPUの意思決定・戦闘イベント/勝敗を高精度再現。戦略マップの移動/外交・内政・ストーリーイベント、RTS固有HQ生産は後段。旧DirectX/DirectMusic/OGG decoder/BGM・SE再生方式の再現は不要。音がなくても戦闘モードの完成判定を妨げない。

- **厳密に合わせる核:** 同じゲーム状態・seed・操作・tick順を与えたときの数値（HP/MP/damage/状態/成長/資金）とCPUの行動選択・目標選定・優先順位、移動/命中/勝敗、シナリオのゲーム効果。原作スクリプトとルールの違いは「仕様差異」として扱い、放置しない。
- **操作互換:** 原作の主要操作、選択/命令結果、ショートカット、ポーズ/速度、入力タイミングの重要な挙動は baseline として保持。**原作UIの不便さ・画素・ウィンドウ形式は再現必須ではない。** 便利な入力・表示は別層で改善する。
- **再現不要:** Ghidra関数名/ABIを1対1で実装、旧ランタイム/DirectXそのもの、原作者のC++ソース階層、全画像のピクセル完全一致、旧EXEへのバイナリプラグイン互換、saveファイルの暗号化乱数鍵までの完全同一性（読み取り/必要な移行は別）。
- **モード分離:** core rulesは原作基準を保つ。操作UIや描画はmodern化してもcore状態に意図せず影響しない。天候・土砂崩れ等ゲームルールを変える追加ギミックは別機能フラグ/追加modeで管理し、baseline OFF の回帰を維持する。
- **成果の順番（v1.2更新）:** 最速G0汎用ウィンドウ→**BG1通常戦闘画面→BG2戦闘操作→BG3スキル実行→BG4戦闘CPU・イベント・勝敗→BG5遊べる通常戦闘→BG6全スキル効果・CPU判断・ゲーム数値が原作と高精度一致**。戦略G1/G2/G3、内政、ストーリーはその後に再優先化する。G7の独自機能はゲーム核を壊さないflag下なら並行開発可。
- **重要な留保:** 元のCPUが非決定的な入力（実時計・浮動小数点環境等）を読む場合、同seedだけで一律に完全一致とは言えない。追加入力を固定し比較できる条件と、統計的・動作カテゴリ別に検証すべき条件をQAで明示する。

## 0. 何が「完成」なのか

- **自動逆コンパイル文書の生成:** 保存済Ghidra index 10,257/10,257件は済。これは原作者のコンパイル可能なC++ソースでも意味検証済み10,257関数でもない。
- **ゲーム動作に必要な部分の意味復元:** 重要な関数の型・値・ABI・副作用をnative命令＋複数の証拠で精密検証する。旧EXE全10,257関数を元通りに復元することは完了条件ではない。
- **ゲームの最初の起動:** 原作EXEに依存しない新EXEがウィンドウを開いて閉じられるところまで（G0）。全関数の精密復元も戦闘実装も必須ではない。
- **見えるゲーム:** タイトル・原作素材の戦略マップ・領地等の表示（G1）。
- **操作できるゲーム:** 選択・クリック・画面UI（G2）。原作主要コマンドの入力意味論を追跡し、UIだけ改善してよい。**一ターン遊べる**状態（G3）はさらに別。
- **戦闘を含むゲーム:** 1v1を最後まで動かせる（G4）＋新エンジンでsave/loadが動く（G5）。
- **ゲーム性の原作忠実再現:** 原作実機の同条件入力に対し、戦闘数値・AI判断・ターン経済・イベント・勝敗ルール・主要操作結果が検証できる（G6）。旧EXE内部や全ファイルフォーマットの完全互換は不要。天候等Enhanced（G7）は分離フラグ・退行防止が整えば並行開発可。

「初回起動に18か月かかる」とはしない。G0の実日数は技術選定・最初のビルド・実機確認を行ってから根拠付きで測定する。**機能ごとの速度が実測できるまで残工数の月数・全体パーセントを捏造しない。**

## 2. 状態と工数の定義

| 状態 | 意味 |
|---|---|
| DONE | 完了条件を証拠で満たした。再検証で欠陥発見ならREOPENできる |
| PARTIAL | 仕様やコードの一部が存在するが、記載の受入条件には未達 |
| READY | 依存を考慮して今すぐ開始可能（自動的に作業開始した意味ではない） |
| WAIT | 依存の未完了・入力不足などにより完了できない。必要な局所調査は可能 |
| BLOCKED | 安全拒否、権限、資料欠落、競合で停止。理由・解除条件必須 |
| SPLIT / MERGED / DROPPED | 分割・統合・廃止済みの履歴。**IDは消さず再利用しない** |

P0=**通常戦闘モードをまず完成させるために必須**（新EXE起動、描画、技能の結果、戦闘CPU、勝敗、検証）。P1=戦略・内政・ストーリー・独立RTSなどの次段階、または追加品質、P2=独自改善。※ v1.2で旧P0の戦略系は多くをP1へ変更。**WIP制限：一AIが同時に編集するDEVタスクは原則1件、全体で同一成果物を編集する担当は1者。** 他AIはまず提案と証拠を担当資料へ記録、管理者だけが本台帳へ反映する。

表の「対応研究T」は**研究正本のownerを尊重するための検索キー**。DA/CB/BT等のDEV担当者がA〜E研究レーンのファイルを編集してよいという意味ではない。完了時は状態だけでなく証拠と受入条件を検証してから閉じる。

## 4. 発見・変更に強い運用規則

1. **見つからなかった新機能・サブシステム:** 一時的に `PROPOSED` 案を「変更履歴」に載せ、同じT-IDや既存タスクとの重複を調べ、受入条件・既存証拠・依存先を追加してから**末尾の未使用連番で新ID**（例 `CB-08`, `BT-09`）を登録。**既存IDを振り直さない。** 未調査でもP0なら提案だけ先に記録する。
2. **タスクが大きすぎる/前提が変わった:** 親タスクを `SPLIT`、元の要求とリンクを履歴に残し、実作業を新しい連番の子IDへ分割する。親と子を同時に完了数へ数えない。子の全受入条件が揃うまで親はDONEにならない。
3. **重複していた/不適切だった:** 主となるタスクを1つ残し、不要側を `MERGED` または `DROPPED`、理由・移行した証拠・依存ID変更を変更履歴に残す。既存の成功テストは消さない。
4. **間違いが発見された:** 最初に `REOPEN`、その時点で危険な元式や件数を `SUPERSEDED` と記録。どの上位マイルストーンが再検証必要かを明示。新たな正しさを示すnative/byte/golden根拠と誤りの再発を検知する試験が揃うまでDONEへ戻さない。
5. **BLOCKEDや安全拒否:** 拒否した具体的な操作と理由を記録し、シェルやツールを変えて迂回しない。可能な既保存証拠への読取分析だけを継続し、解除承認がなければ停止したまま。競合作業は短い再試行→次回runへ持越し。**スケジュール自体を勝手に停止しない。**
6. **週次のスコープ/納期見直し:** 実際に完了したタスクの経過時間と難度を記録し、工程別実績レンジから残日数を更新。新タスクで分母が増えても過去履歴を消さない。「X%完了」は工数重み未設定の間は禁止。**G0最短起動とG6戦闘・CPU・操作・ゲーム性の高精度再現を別々に見積もる**。
7. **エビデンスの昇格:** `EXTRACTED`（疑似C採取）→`STATIC_VERIFIED`（原命令・呼出ABI・フィールド確認）→`MODEL_TESTED`（局所合成試験）→`TARGET_OBSERVED`（原作で合法観測）→`BEHAVIOR_MATCH`（新ゲームとの同条件の結果一致）。
   `BEHAVIOR_MATCH`には `EXACT`（同じseed/tick/状態で数値・行動一致）、`OBSERVABLE`（可視の操作結果・イベント順一致）、`STATISTICAL`（隠れたRNGや実時計により厳密一致不可、理由と許容差を明記）という詳細判定を付ける。**ゲーム性の再現ではランダムの再現性・CPU分岐順のEXACTを優先し、統計的に似たAIで代用しない。** 逆コンパイル数・合成テスト数を成果のstrict一致へ自動加算しない。
8. **複数AIと正式研究レーン:** 原本、研究A〜E、他AIの `peer_script01_*`、MASTER、READMEなど担当外は原則read-only。DEVの新規ファイルのみを書く。同じ台帳を同時編集する場合は更新前に最新版とmtimeを再読し、差分を持越して再照合（上書き禁止）。新worktreeや別フォルダは指示なく増やさない。

## 5. 作業の基本サイクルと報告方法

- **開始:** MASTERと規約、最新handoff、WBS版番号、予定タスクの依存・担当・既存証拠・ファイル所有権を読む。
- **選択:** 原則1〜3件。ただし並列担当が同じファイルを変更しないよう予約/状態を確認。**通常戦闘だけに専念する優先順：BT-01→02→03→BF-04/05（戦場画面）、並行BF-02（全skill棚卸）・BF-03/08（runtime/tick）、その後BF-06/07（表示入力）、BF-09/10/11（スキル・演出）、BF-12/13（CPU・勝敗）、BF-14/15/16/17/18（通し動作・検証）。** WD-07や戦略/物語は通常戦闘の主要P0を片付けるまで後回し。

- **終了:** 成否、証拠、コマンドとexit、依存/残件、新発見、変更履歴を更新。エラーや未知の経路は「PASS」にしない。
- **表示:** 毎回 `G0～G7達成状況`、`DONE/PARTIAL/READY/WAIT/BLOCKED`、直近完了3件、次の重要3件、計画との差分、更新された工数レンジのみ簡潔に報告。
