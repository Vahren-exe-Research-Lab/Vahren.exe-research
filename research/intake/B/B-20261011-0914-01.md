## Bounded observations from saved x86 (STATIC_PRIOR)

1. `0x5158A0`: entry `CMP ECX,EDX` and `0x5158A2 JE 0x5158D2` skip all data writes if the input range is empty. For a nonempty range, six DWORD stores at offsets `0x0,0x4,0x8,0xC,0x10,0x14` and advances of `0x18` imply a **24-byte record copy**, not a vector destructor.
2. `0x514F4C..0x514F62`: source scratch begin `[0xAC09EC]` vs end `[0xAC09F0]`. When nonempty, `0x514F5D CALL 0x5158A0` passes identical `ECX=EDX=end`; the helper returns with original `EAX=begin`. `0x514F62` writes that value to scratch end, so **begin=end**, a *logical empty vector*. Stored record bytes need not be erased.
3. `0x57BA6C..0x57BA89`: Unit-local cached begin `+0x1E584` and end `+0x1E588` are checked; on nonempty branch `0x57BA84 CALL 0x5158A0` again receives `ECX=EDX` and `0x57BA89` writes returned begin to end. This is a **conditional logical clear for this caller**, not a guarantee every support-search branch clears its cache.
4. A *different* branch can take a separate support-cache helper; the two branch-specific effects must not be collapsed into one unconditional clear, nor should a stale backing allocation be called deallocated.
